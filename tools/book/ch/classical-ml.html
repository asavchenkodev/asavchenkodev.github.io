Classical machine learning and ML fundamentals

How a model learns from examples, why it fails on new data, and how the main model families work: linear and logistic regression, trees, random forests and gradient boosting, SVMs, k-NN and naive Bayes, clustering and PCA. Then the craft around them that decides whether a model is any good: cross-validation, metrics and thresholds, class imbalance, feature engineering, leakage and SHAP. The running example is a customer-churn table of 50,000 subscribers solved with every model family, plus house-price regression on the California housing data. Every number comes from a script in the experiments folder.

1The big picture: learning a function from examples

Machine learning exists because many useful rules are too complicated to write down but easy to show by example. A model is a function with adjustable parameters; learning means choosing the parameters so that the function does well on data it has not seen. Everything in this chapter is a variation on that sentence.

1.1Rules that are easier to show than to write

Imagine a subscription business (a streaming service, a mobile operator, a SaaS product) that loses about one customer in seven every quarter. The retention team can call a few thousand customers a month and offer a discount, and they want to call the right ones. An engineer could try to write rules: "customers on a monthly contract with more than three support calls and no login for two weeks are at risk". Such rules capture some truth, but they are brittle. Each rule has hand-picked thresholds, rules interact, and nobody knows how much each one is worth. Meanwhile the company already has a table with one row per customer, dozens of columns, and a record of who actually left. That table is a set of worked examples of the rule we want.

Supervised machine learning turns this around. We choose a family of functions \(f_\theta(x)\) with parameters \(\theta\): a weighted sum, a tree of if-then splits, a sum of hundreds of small trees. We choose a loss that measures how wrong a prediction is for one example. And we let an optimiser pick the \(\theta\) that makes the average loss on the known examples small. Three components, always: the model family (what shapes of rule are possible), the loss (what "wrong" means), and the optimiser (how to search the parameters). Linear regression is a weighted sum, squared error and a closed-form solution; gradient boosting is a sum of trees, log loss and greedy tree building. Learning to see every method as these three choices is the fastest way to understand a new one.

The twist that makes machine learning a discipline rather than curve fitting is that we do not care about the examples we already have. We know who left last quarter. We care about the customers who will leave next quarter. The real objective is the error on new data drawn from the same process, the generalisation error, and the training error is only a biased estimate of it. Chapter 2 is about the gap between the two, and Chapters 7 to 9 are about measuring it honestly.

Talk track

"A machine-learning model is a function with knobs. We pick a family of functions, a loss that says what a bad prediction costs, and an optimiser that turns the knobs to make the loss small on historical examples. The whole difficulty is that we are graded on future examples, so we need to control how flexible the function is and measure it on data it never saw."

1.2The running examples: churn and house prices

The main example is a churn table: 50,000 customers, one row each, with tenure in months, contract type (monthly, one-year, two-year), monthly charges, support calls in the last 90 days, days since the last login, number of products, payment method, age, a recent price increase, a region code, and an ID-like number with no meaning. The label is whether the customer left within the next 30 days; 15.3 percent did. The table is synthetic, generated by experiments/churn_data.py with patterns that real churn data shows: new customers leave more and the effect fades after a year; price matters only for customers without a contract; a third complaint call is a tipping point; disengagement saturates; customers with several products stay.

Using synthetic data has one large advantage for learning: we know each customer's true churn probability. That gives a Bayes ceiling, the best score any model could ever reach on this data, because even a perfect model cannot predict a coin flip. On the 10,000 test customers the true probabilities reach a ROC-AUC of 0.822 and a PR-AUC of 0.488 (both explained in Chapter 8). When a model scores 0.817, we know that it is half a point from perfect, not twenty points, and that no amount of tuning will find the missing twenty. On real data the ceiling is unknown, which is one reason teams over-invest in model tuning.

The second example is house-price regression on the California housing data from the 1990 census: 20,640 districts with median income, house age, rooms, population, location and distance to the ocean, and the median house value as the target (median $179,700; 4.7 percent of districts are capped at $500,001, a quirk worth remembering). It is the standard teaching set for regression and appears in Chapters 3 and 8.

Numbers

Churn table: 50,000 rows, 11 features, 15.3 percent churners, 40,000 train / 10,000 test (stratified). Bayes ceiling on the test set: ROC-AUC 0.822, PR-AUC 0.488, log loss 0.332. Churn by contract: monthly 23.5 percent, one-year 8.3 percent, two-year 1.8 percent. House prices: 20,640 districts, 16,512 train / 4,128 test; predicting the mean gives an RMSE of $114.5k.

1.3Four learning setups

The setups differ in what the data tells the learner (Figure 1.1). In supervised learning every training example comes with the answer: customer features and whether they churned, a house and its price, an email and "spam". If the answer is a category the task is classification; if it is a number, regression. Most business ML is supervised, and most of this chapter is about it.

In unsupervised learning there is no answer column. The goal is to find structure: groups of similar customers (clustering), a few directions that summarise many correlated columns (dimensionality reduction), or rows that look unlike the rest (anomaly detection). The difficulty is that there is no ground truth to score against, so "good" depends on what the result is used for. Chapter 6 covers the main methods.

Self-supervised learning manufactures labels from the data itself: hide a word and predict it, hide an image patch and reconstruct it, predict the next frame. No human labels are needed, so it scales to billions of examples, and the representation the model learns becomes the starting point for supervised tasks with few labels. It is how large language models and modern image encoders are pretrained (see GenAI 15.2 and Deep learning 4.4). In classical tabular ML it plays almost no role.

Reinforcement learning learns from consequences rather than answers. An agent takes actions in an environment and receives a reward, often delayed: a game won after 200 moves, a click after a recommendation. The learner must explore and assign credit to earlier actions. RL powers game-playing systems, some robotics and recommendation, and the preference-training step of LLMs (GenAI 3.4). For a churn team, choosing which offer to make could be framed as RL (a contextual bandit), but predicting who will leave is plain supervised learning.

Interesting detail

Semi-supervised learning (a few labels plus many unlabelled rows) and weak supervision (noisy labels from heuristics) sit between the setups. In practice the most common version is pseudo-labelling: train on the labelled rows, predict the unlabelled ones, keep the confident predictions as extra training data. It helps when unlabelled data is plentiful and the model is already decent; it reinforces the model's own mistakes when it is not.

1.4The workflow, and where the model fits in it

A classical ML project has the same shape in fraud, churn, credit scoring, demand forecasting and predictive maintenance (Figure 1.2). It starts with a decision: whom to call, which transaction to block, how much stock to order. The decision defines the label, the moment of prediction, and the cost of each kind of mistake, and these three choices matter more than the choice of algorithm. Then come data (one row per entity per point in time), a split that imitates the future, features, several model families, evaluation with a metric that reflects the decision, a threshold, and finally deployment and monitoring.

The chapter follows the model families first (Chapters 3 to 6) because they are the shared vocabulary of the field, then the evaluation craft (Chapters 7 to 9), which is what decides real projects. Chapter 10 puts the churn project together.

Pitfall

Starting with the algorithm. A team that opens a notebook, loads every column and tunes XGBoost for a week often discovers later that the label was defined at the wrong time, that two columns were filled in after the customer left, or that the business cannot act on predictions for customers who leave within 30 days anyway. Write down the decision, the prediction time and the cost of errors before the first model.

2Generalisation: bias, variance, underfitting and overfitting

A model that memorises its training data looks perfect and is useless. A model too rigid to follow the data is useless in a different way. The whole art of model building is choosing the flexibility between these two, and the bias-variance picture explains why there is a best point.

2.1Training error is not the goal

Train an unrestricted decision tree on the 40,000 churn customers. It keeps splitting until every leaf holds customers with the same label, so its training ROC-AUC is exactly 1.000: it has memorised every customer. On the 10,000 test customers its ROC-AUC is 0.602, barely better than guessing and far below a simple logistic regression (0.806). The tree learned the real patterns plus every accident of the training sample: the particular 34-year-old on a two-year contract who happened to leave. Accidents do not repeat, so on new customers the memorised detail is noise.

This is overfitting: low training error, high test error, a large gap between them. The opposite, underfitting, is a model that cannot express the pattern at all: a straight line through a curve, or a tree of depth one for a problem with ten interacting causes. Its training and test errors are both high and close together. The two failures need opposite fixes, which is why diagnosing which one you have is the first step of any model improvement.

Why it matters

Every hyperparameter you will meet (tree depth, number of neighbours, regularisation strength, learning rate, number of boosting rounds) is a dial between underfitting and overfitting. Knowing which side you are on tells you which way to turn every dial at once.

2.2Bias and variance: two ways to be wrong

Think of training as a random process: the training set is one sample out of many possible samples, and a different sample would give a different model. For a fixed input \(x\), the expected squared error of the model over all possible training sets splits into three parts:

\[ \mathbb{E}\big[(y - \hat f(x))^2\big] = \underbrace{\big(f(x) - \mathbb{E}[\hat f(x)]\big)^2}_{\text{bias}^2} + \underbrace{\mathbb{E}\big[(\hat f(x) - \mathbb{E}[\hat f(x)])^2\big]}_{\text{variance}} + \underbrace{\sigma^2}_{\text{noise}} \]

Bias is how far the average model (averaged over many training sets) is from the truth: the error the model family makes even with unlimited luck. A straight line fitted to a sine wave has high bias. Variance is how much the model jumps around from one training set to the next: a degree-12 polynomial through 20 points wiggles differently for every sample. Noise is the part of \(y\) that no function of \(x\) can predict; it is the floor. More flexible models have lower bias and higher variance, so the total error has a minimum somewhere in between (Figure 2.1).

The decomposition is exact for squared error and gives intuition for every other loss. Figure 2.2 lets you feel it. Raise the degree and watch the training error fall steadily while the test error first falls, then rises. Then keep the degree at 12 and turn up the ridge penalty (Section 3.2): the wiggles disappear, variance drops from 3.17 to 0.05 at a penalty of 0.01, and the expected test error returns to 0.144, close to the best low-degree model. Push the penalty to 0.1 and the curve becomes too stiff: bias rises to 0.058. Change the sample with the third slider to see variance directly: a high-degree unpenalised fit changes shape completely between samples.

Interesting detail

Very large models break the simple U-curve. Past the point where a model can fit the training data exactly, test error can fall again as the model grows, because among all functions that fit the data, gradient descent and implicit regularisation find smooth ones. This "double descent" is why neural networks with more parameters than examples still generalise. For the model families in this chapter, which are regularised explicitly, the classical U-curve is the right mental model.

2.3Learning curves: more data, or a different model?

A learning curve plots training and validation scores against the number of training rows (Figure 2.3). It answers the most expensive question in a project: will collecting more data help? With 500 churn customers, LightGBM scores 0.994 on its own training data and 0.726 on the test set: a 27-point gap, textbook variance. Logistic regression, far less flexible, scores 0.761 on test, better than the boosted trees. As the training set grows the boosted model's gap closes (0.843 train, 0.817 test at 40,000 rows) and it overtakes logistic regression at about 10,000 rows. Logistic regression stops improving after 10,000 rows (0.805 to 0.806): it has hit its bias, and more data cannot fix a model that cannot express the pattern.

The reading rule: if the curves are far apart and the validation curve is still rising, get more data or regularise more. If they have met and the level is not good enough, add features or use a more flexible model. If both curves are high and close, you are near the noise floor, and the remaining effort should go to the decision (threshold, costs) rather than the model.

In practice

sklearn.model_selection.learning_curve computes the curves with cross-validation. It is cheap insurance before a labelling budget is approved: if the curve has flattened at 20,000 rows, labelling another 100,000 will buy little.

2.4Regularisation: the dial between the two failures

Regularisation is anything that limits how closely a model can follow the training data, trading a little bias for a large reduction in variance. Every model family has its own form. Linear models add a penalty on the size of the weights (L2 or L1, Section 3.2). Trees limit depth, minimum leaf size or the number of leaves. Ensembles average many models (random forests) or take small steps (the learning rate in boosting). k-NN averages more neighbours. SVMs trade margin width against training errors through C. Training can stop early, before the model has fitted the noise. And the cheapest regulariser of all is more data, which shrinks variance without adding bias.

Regularisation strength is a hyperparameter: it is not learned from the training data by the optimiser (the optimiser would always choose "no penalty", which minimises training error) but chosen by measuring validation performance, the subject of Chapter 7.

Pitfall

Judging regularisation on the training set. A penalty always makes the training error worse; that is its job. The only fair judge is held-out data. In Figure 2.2, a penalty of 10⁻² at degree 12 raises the training error slightly but cuts the expected test error from 3.27 to 0.14.

3Linear models: regression, regularisation and logistic regression

Linear models are the baseline every tabular project should start with: fast, stable, interpretable through their weights, and often within a few points of the best model. Understanding them also explains the vocabulary of the rest of the field: loss, likelihood, regularisation, log-odds and calibration.

3.1Linear regression: least squares and the likelihood view

Linear regression predicts a number as a weighted sum of the features plus an intercept, \(\hat y = w^\top x + b\). It chooses the weights that minimise the sum of squared residuals, \(\sum_i (y_i - w^\top x_i - b)^2\) (Figure 3.1). Because the loss is a quadratic bowl in the weights, there is one minimum and it has a closed form, the normal equations \(w = (X^\top X)^{-1} X^\top y\). Libraries actually solve it with a QR or SVD decomposition, which is more stable when features are correlated (Mathematics 2), or with gradient methods when the data does not fit in memory.

Why squares and not absolute values? The maximum-likelihood view answers it. Assume each price is the line plus Gaussian noise with constant variance. The probability of seeing the data is a product of Gaussian densities, and its logarithm is, up to constants, minus the sum of squared residuals. So least squares is exactly "the line under which the observed data is most probable, if the noise is Gaussian". Change the assumption and the loss changes with it: Laplace noise gives absolute error (median regression, robust to outliers), Poisson noise gives Poisson regression for counts, Bernoulli noise gives logistic regression (Section 3.3). The loss is a statement about the noise.

On the housing test set, linear regression with all features reaches an RMSE of $69.1k and an R² of 0.635: it explains about two thirds of the variance in prices. Median income alone is the strongest feature, worth about $79k per standard deviation. The remaining error is not noise; it is structure the line cannot express, such as the location effect (coastal versus inland, the Bay Area versus the Central Valley), which is strongly non-linear in latitude and longitude. A gradient-boosted model on the same features reaches $43.0k (Section 8.6).

Pitfall

Reading weights as importance when features are on different scales or correlated. A weight of 0.0004 on population and 79,000 on income says nothing about which matters more until both are standardised; and when two features are strongly correlated (rooms and bedrooms), their weights can take large opposite signs that cancel. Standardise, and inspect the correlation matrix before interpreting coefficients.

3.2Regularisation: ridge, lasso and elastic net

When there are many features relative to rows, or features are strongly correlated, least squares becomes unstable: tiny changes in the data swing the weights wildly, which is variance. Regularisation adds a penalty on the weights to the loss. Ridge (L2) adds \(\alpha \sum_j w_j^2\); lasso (L1) adds \(\alpha \sum_j |w_j|\); elastic net mixes both. Ridge shrinks all weights smoothly towards zero and handles correlated features by sharing weight between them. Lasso drives some weights to exactly zero, so it also selects features.

Why does L1 give exact zeros and L2 does not? Picture the penalty as a budget: the weights must stay inside a region, a circle for L2, a diamond for L1. The solution is where the smallest loss contour around the unpenalised solution first touches the region (Figure 3.2, first tab). A circle has no corners, so the touching point generally has both weights non-zero. A diamond has corners on the axes, and an ellipse usually hits a corner first, where one weight is exactly zero. In more dimensions the L1 ball has many corners and edges, and many weights land on zero.

A real test makes the point. Take only 1,000 housing districts, create all polynomial terms up to degree 3 of the 11 numeric features (363 features from 11), and fit them. Plain least squares reaches a training RMSE of $41.9k and a test RMSE of $7.5 million: the weights reach tens of millions to fit the training points and the predictions explode on new districts. Ridge with a modest penalty brings the test error to $115k; cross-validated ridge to $79.8k. Cross-validated lasso keeps 71 of the 363 terms and reaches $68.2k, better than the plain linear model on the original 11 features ($75.2k on the same 1,000 rows). The penalty turned an unusable model into the best linear model in the comparison.

Numbers

Degree-3 polynomial on 1,000 housing rows (experiments/poly_check.py): OLS train $41.9k / test $7,455k; ridge α=3 train $48.2k / test $115k; RidgeCV (α=100) $56.2k / $79.8k; LassoCV (α≈960) $56.2k / $68.2k with 71 of 363 non-zero. Lasso path on the full data: 3 features at α=15, 11 at α=2.3, 15 of 16 at α=0.05.

Pitfall

Regularising unscaled features. The penalty treats all weights alike, so a feature measured in dollars (small weight) is barely penalised while one measured in thousands of dollars (large weight) is penalised hard. Always standardise before ridge or lasso; scikit-learn's linear models do not do it for you. Also, the intercept is not penalised, and lasso's choice among correlated features is somewhat arbitrary: it picks one and drops the others, so a dropped feature is not proven useless.

3.3Logistic regression: a linear score turned into a probability

For churn, the answer is yes or no, and we want a probability. Logistic regression computes the same linear score \(z = w^\top x + b\) and squeezes it through the sigmoid \(p = 1/(1+e^{-z})\) (Figure 3.3, left). The score \(z\) is the log-odds, \(\log\frac{p}{1-p}\), so each weight has a clean meaning: increasing feature \(j\) by one unit adds \(w_j\) to the log-odds, multiplying the odds of churn by \(e^{w_j}\). "A monthly contract multiplies the odds of churn by 3.5" is a sentence a business can use.

The loss follows from the likelihood again. Each label is a Bernoulli outcome with probability \(p_i\); the negative log-likelihood is the log loss (binary cross-entropy), \(-\sum_i [y_i \log p_i + (1-y_i)\log(1-p_i)]\). It punishes confident mistakes severely: predicting 0.01 for a customer who leaves costs 4.6, predicting 0.5 costs 0.69 (Figure 3.3, right). The loss is convex in the weights, so the optimiser (L-BFGS or Newton's method in scikit-learn) always finds the global minimum, but there is no closed form. When classes are perfectly separable the weights grow without bound, which is one reason scikit-learn applies an L2 penalty by default (C=1.0, where C is the inverse of the penalty strength).

On the churn table, logistic regression on the raw features reaches a test ROC-AUC of 0.806 and a log loss of 0.344, against a ceiling of 0.822 and 0.332. Its probabilities are well calibrated out of the box: of the 1,112 test customers it scores between 0.25 and 0.35, 29.8 percent leave (expected calibration error 0.012, experiments/calibration.py). That property, which comes from fitting the log loss directly, is valuable when the probabilities feed a cost calculation (Section 8.4), and many more powerful models lack it.

Logistic regression extends to several classes with the softmax: one score per class, exponentiated and normalised. Its decision boundary is always a straight line (a hyperplane) in feature space, which is its strength (stable, little variance) and its limit (Section 5.5).

Talk track

"Logistic regression is linear regression on the log-odds. It is trained by maximising the Bernoulli likelihood, which is the log loss. Each weight says how much a one-unit change in a feature multiplies the odds. It is convex, fast, calibrated, and its boundary is linear, so it underfits interactions unless you add them as features."

3.4Making linear models work: encoding, scaling and interactions

A linear model can only add up its inputs, so the features must already be in a form where adding makes sense. Categorical columns become one-hot indicators (contract = monthly, one-year, two-year as three 0/1 columns). Numeric columns are standardised (zero mean, unit variance) so that the optimiser converges and the penalty is fair. Skewed amounts are often log-transformed. And non-linear effects must be supplied by hand: a spline or binned version of tenure, an indicator for "three or more calls", a product term for "price increase × young account".

The churn experiment shows how much this matters. Adding five features that encode the true shapes (an exponential decay of tenure, the call threshold, the saturating login effect, the charges-by-contract and price-by-tenure interactions) lifts logistic regression from 0.806 to 0.822, exactly the Bayes ceiling, beating every tree ensemble. That is the honest summary of linear models: with the right features they are as good as anything, and the hard part is knowing the right features. On real data you never know the true functional form, which is why tree ensembles, which discover non-linearity and interactions themselves, win in practice (Section 4.5).

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.linear_model import LogisticRegression

num = ["tenure_months", "monthly_charges", "support_calls_90d", "days_since_login", "num_products", "age"]
cat = ["contract", "payment", "region"]
pre = ColumnTransformer([("num", StandardScaler(), num),
                         ("cat", OneHotEncoder(handle_unknown="ignore"), cat)])
model = make_pipeline(pre, LogisticRegression(C=1.0, max_iter=2000))
model.fit(X_train, y_train)                      # scaler and encoder are fitted on training rows only
p_churn = model.predict_proba(X_test)[:, 1]
In practice

Every tabular project should have a regularised logistic (or linear) regression as its first model. It takes minutes, sets the bar any complex model must clear, exposes data bugs through absurd coefficients, and is sometimes the model that ships: credit scoring is still dominated by logistic regression on binned features (scorecards), because regulators require explanations per applicant and stable behaviour.

4Trees and ensembles: decision trees, random forests and gradient boosting

A single decision tree is easy to read and easy to overfit. Averaging many decorrelated trees (random forests) removes most of the variance; adding many small trees, each correcting the last (gradient boosting), removes the bias as well. Gradient-boosted trees are the default model for tabular data in industry, and this chapter explains why.

4.1Decision trees: twenty questions, chosen greedily

A decision tree predicts by asking a sequence of yes/no questions about single features: "tenure ≤ 8.5 months?", then "support calls ≤ 2.5?", and so on, until it reaches a leaf that holds a prediction, the churn rate (or average price) of the training rows that ended there. Geometrically, each question cuts the feature space with a line parallel to an axis, so a tree partitions the space into rectangles and predicts a constant in each (Figure 4.1).

Finding the best tree is computationally hopeless, so trees are grown greedily. At each node the algorithm tries every feature and every threshold between observed values and picks the split that most reduces impurity, a measure of how mixed the labels are. For classification the usual measure is the Gini impurity \(1 - \sum_k p_k^2\) (the chance that two random rows in the node disagree) or the entropy \(-\sum_k p_k \log p_k\); for regression it is the variance. The worked example in Figure 4.1 uses the 27,372 monthly-contract customers, 23.5 percent of whom churn. The root has Gini \(1 - 0.235^2 - 0.765^2 = 0.359\). Splitting at tenure 8.5 months sends 5,827 customers left with a churn rate of 38.8 percent (Gini 0.475) and 21,545 right with 19.3 percent (Gini 0.312). The weighted impurity after the split is \(0.213 \times 0.475 + 0.787 \times 0.312 = 0.346\), a reduction of 0.013, the best available among all features and thresholds. The process repeats in each child until a stopping rule (maximum depth, minimum rows per leaf) fires.

Trees have properties that make them attractive for tabular data. They need no scaling (a threshold on dollars works like a threshold on standardised dollars), they handle mixed numeric and categorical features, they capture interactions naturally (the calls split happens separately for new and old customers), they are insensitive to monotone transformations and outliers in the inputs, and many implementations handle missing values by learning which branch the missing rows should take. Their weakness is variance: a small change in the data can change the root split and with it the whole tree. Grown without limits, a tree memorises the training set, as the 1.000 training versus 0.602 test AUC in Section 2.1 showed. Limited to depth 6 with at least 50 rows per leaf, it reaches 0.791: decent, but well below the ensembles.

Interesting detail

CART, the algorithm behind scikit-learn's trees, makes only binary splits and uses Gini by default. Choosing between Gini and entropy almost never matters; choosing the depth and leaf size always does. A tree with depth \(d\) has up to \(2^d\) leaves, so depth 20 means a million potential rectangles, more than most data sets have rows.

4.2Random forests: averaging away the variance

If one deep tree has low bias and high variance, averaging many of them should keep the low bias and reduce the variance, just as averaging noisy measurements does. The catch is that trees trained on the same data are nearly identical, and averaging identical things changes nothing. The variance of an average of \(B\) predictors, each with variance \(\sigma^2\) and pairwise correlation \(\rho\), is \(\rho\sigma^2 + (1-\rho)\sigma^2/B\) (Figure 4.2). More trees remove the second term; only decorrelation reduces the first.

Bagging (bootstrap aggregating, Breiman 1996) decorrelates trees by training each on a bootstrap sample: as many rows as the training set, drawn with replacement, so each tree sees about 63 percent of the distinct rows. Random forests (Breiman 2001) add a second source of randomness: at each split, only a random subset of the features is considered (by default \(\sqrt{p}\) for classification). This stops every tree from splitting on the same dominant feature at the root and lowers \(\rho\) much further. The trees are grown deep, with little or no pruning, because the averaging takes care of the variance.

Two by-products are useful. The rows a tree did not see (about 37 percent) are its out-of-bag rows, and predicting each row only with trees that did not train on it gives a free validation estimate without a held-out set. And because adding trees never increases variance, the number of trees is not a regularisation dial: more is better until the improvement stops being worth the compute, typically a few hundred.

On the churn table, a 500-tree forest with at least 20 rows per leaf reaches a test AUC of 0.816 (training AUC 0.876), 2.5 points better than the best single tree. Random forests are hard to get badly wrong: the defaults work, they rarely overfit catastrophically, and they parallelise perfectly across trees. Their weaknesses are size (hundreds of deep trees can be hundreds of megabytes), slower prediction, and probabilities that are pulled towards the middle, because averaging votes rarely produces values near 0 or 1.

Talk track

"A random forest averages hundreds of deep trees, each trained on a bootstrap sample and allowed to look at a random subset of features at each split. Deep trees have low bias and high variance; averaging decorrelated trees removes most of the variance. More trees never hurt, they just cost time."

4.3Gradient boosting: many small trees, each fixing the last

Boosting takes the opposite route. Instead of averaging strong, independent models, it adds weak models one after another, each trained to fix what the current ensemble gets wrong. For squared error the idea is easy to see (Figure 4.3). Start by predicting the mean. Compute the residuals, the part of each target the model has not explained yet. Fit a small tree to the residuals. Add a fraction of that tree (the learning rate, say 0.3) to the model. Recompute the residuals and repeat. Each step removes a little of the remaining structure. On the toy data, the training RMSE falls from 1.64 (mean only) to 1.36 after one tree, 0.89 after ten and 0.35 after a hundred, which is below the noise level of 0.45: by then the ensemble has started fitting noise, and a validation set would tell us to stop earlier.

Why "gradient"? For squared error, the residual \(y - F(x)\) is the negative gradient of the loss with respect to the current prediction. Friedman's insight (2001) was that the same recipe works for any differentiable loss: compute the negative gradient of the loss for each training row (the pseudo-residual), fit a regression tree to it, and take a step. For log loss the pseudo-residual is \(y - p\), the difference between the label and the predicted probability, so each tree pushes the log-odds of misclassified customers in the right direction. Boosting is gradient descent, but in function space: each step adds a function (a tree) rather than updating a parameter vector.

The hyperparameters follow from this picture. The learning rate (typically 0.01 to 0.1) sets the step size: smaller steps need more trees but generalise better, the classic shrinkage trade-off. The number of trees is chosen by early stopping: keep adding trees until the validation loss has not improved for, say, 50 rounds. Tree size (depth 3 to 8, or 15 to 255 leaves) controls how many features can interact in one tree. Row and column subsampling per tree (0.5 to 0.9) add randomness that decorrelates the trees, as in forests. And L1/L2 penalties on the leaf values, plus a minimum number of rows or Hessian weight per leaf, regularise each tree.

Why it matters

Boosting reduces bias (each tree fixes systematic errors) and, with shrinkage and subsampling, controls variance. That is why it usually beats random forests, which can only reduce variance: a forest of deep trees cannot become less biased than one deep tree.

Pitfall

Tuning boosting without early stopping. With a fixed 1,000 trees and a high learning rate the model overfits; with a low learning rate and too few trees it underfits. Set a generous maximum, a learning rate around 0.05, and let early stopping on a validation fold choose the number of trees. Then do not report the validation score as the final result: it was used to choose a hyperparameter (Section 7.4).

4.4XGBoost, LightGBM and CatBoost: what each one added

The algorithm is from 2001; the libraries that made it the industry default are from 2014 to 2017, and their contributions are mostly engineering. XGBoost (Chen and Guestrin, 2016) uses a second-order Taylor expansion of the loss, so each tree's leaf values and split gains come from both the gradient and the Hessian of every row, and it adds explicit L1/L2 regularisation of the leaf weights and a minimum gain to split. It handles missing values by learning a default direction at each split, uses sparsity-aware split finding, and parallelises split search across features. It grows trees level by level (all nodes at one depth before the next), limited by max_depth.

LightGBM (Microsoft, 2017) made training fast on large data. It bins each feature into at most 255 buckets once, so split search scans histograms instead of sorted values (XGBoost later adopted the same hist method, now its default). It grows trees leaf-wise: always split the leaf whose split reduces the loss most, limited by num_leaves (Figure 4.4). Leaf-wise trees reach a lower loss with the same number of leaves but can grow deep and overfit on small data, so min_child_samples matters. It also introduced gradient-based one-side sampling (keep rows with large gradients, sample the rest) and bundling of mutually exclusive sparse features. CatBoost (Yandex, 2017) focused on categorical features: it computes target statistics for categories in an "ordered" way, using only rows that come before each row in a random permutation, which avoids the target leakage of naive target encoding (Section 9.2), and it grows symmetric (oblivious) trees that use the same split across a whole level, which are fast to evaluate and naturally regularised.

4.5Why gradient boosting is the default for tabular data

Figure 4.5 puts every model family of this chapter on the churn table. The tree ensembles (random forest, HistGradientBoosting, XGBoost, LightGBM) cluster at 0.816 to 0.818 test AUC, within half a point of the Bayes ceiling of 0.822, with no feature engineering at all. A small neural network (MLP) gets close at 0.814, logistic regression on raw features reaches 0.806, and naive Bayes, a depth-6 tree and k-NN sit near 0.79. Logistic regression given the true functional forms reaches the ceiling exactly, which is the instructive outlier: it shows the ensembles won not because they are magic but because they found the non-linear shapes and interactions that the linear model had to be told.

On real tabular data the gap is usually larger, and the reasons are structural. Tabular features are heterogeneous: dollars, counts, days, categories with thousands of levels, each with its own scale and meaning, many irrelevant. Trees are invariant to monotone transformations, ignore irrelevant features by never splitting on them, and model sharp thresholds ("three calls", "contract ends next month") naturally. Neural networks, by contrast, are biased towards smooth functions and are rotation-invariant in a way that mixes informative and uninformative features. A 2022 benchmark by Grinsztajn, Oyallon and Varoquaux on 45 data sets found exactly these reasons: tree ensembles stayed ahead of deep models on medium-sized tabular data (around 10,000 rows) even after extensive tuning of both. Kaggle competitions on tabular data have been won by gradient-boosted trees (often an ensemble of LightGBM, XGBoost and CatBoost with careful features) far more often than by anything else.

Practical reasons add to the accuracy: training in seconds to minutes on a CPU, little preprocessing, native handling of missing values and categoricals, built-in early stopping, robust defaults, mature tooling for explanations (TreeSHAP, Section 9.5), and fast inference that can be compiled to plain C. Neural networks win when the input has structure that trees cannot exploit, such as images, audio, text, sequences of events, or when the tabular data is huge and combined with such inputs. Recent tabular foundation models (TabPFN for small tables, for example) are competitive on small data sets, but they have not displaced boosting as the default.

Talk track

"For tabular data my first serious model is gradient-boosted trees, usually LightGBM or XGBoost with early stopping, after a logistic-regression baseline. Trees handle mixed feature types, thresholds, interactions and missing values without preprocessing, and boosting removes bias while shrinkage and subsampling control variance. Neural networks win on images, text and sequences, not on a table of heterogeneous columns."

5Margins, neighbours and probabilities: SVMs, kernels, k-NN and naive Bayes

Three older families complete the classical toolbox. Each embodies an idea that is still alive elsewhere: maximum margins and the kernel trick, prediction by similarity, and generative modelling with Bayes' rule. They are rarely the best choice for a large table today, but they are worth knowing because they test understanding of geometry and probability.

5.1Support vector machines: the widest street

When two classes can be separated by a straight line, there are infinitely many such lines. The support vector machine picks the one with the widest margin: the line that stays as far as possible from the nearest points of both classes, like the centre line of the widest street that fits between them (Figure 5.1). The intuition is robustness: a boundary far from all training points is less likely to be crossed by small perturbations of new points. Only the points on the edge of the street, the support vectors, determine the solution; all others could move freely without changing it.

Real data overlaps, so the soft-margin SVM allows points inside the street or on the wrong side at a cost. It minimises \(\frac{1}{2}\|w\|^2 + C\sum_i \max(0, 1 - y_i f(x_i))\): a wide margin (small \(\|w\|\)) plus the hinge loss of each point. The hinge loss is zero for points correctly classified beyond the margin and grows linearly for the rest. C is the trade-off: large C punishes violations, giving a narrow margin and low bias; small C allows many violations, giving a wide margin and more regularisation. Compare the hinge loss with the log loss of logistic regression (Figure 5.1, right): they are similar, except that the hinge loss is exactly zero for confident correct points, which is why only some points become support vectors, and why a plain SVM outputs a score, not a probability.

Interesting detail

To get probabilities out of an SVM, scikit-learn's probability=True fits Platt scaling (a logistic regression on the SVM scores) with an internal five-fold cross-validation, which multiplies training time by about five and can make predict_proba disagree with predict near the boundary. The same calibration methods are covered in Neural network training 8.2.

5.2The kernel trick: non-linear boundaries with linear algebra

A linear boundary is often not enough. Suppose customers with medium values of some feature stay and those at both extremes leave. No threshold on that feature separates them, but adding its square as a second feature makes the classes linearly separable (Figure 5.2). In general, mapping the data into a richer feature space \(\phi(x)\) turns a non-linear problem into a linear one. The difficulty is that rich feature spaces are huge: all products of pairs of 100 features already give 5,050 dimensions.

The kernel trick avoids building \(\phi(x)\) at all. The SVM's optimisation and its predictions depend on the data only through dot products \(\phi(x_i)^\top\phi(x_j)\). A kernel is a function \(k(x_i, x_j)\) that computes this dot product directly from the original inputs. The polynomial kernel \((x_i^\top x_j + c)^d\) corresponds to all products of up to \(d\) features; the RBF (Gaussian) kernel \(\exp(-\gamma\|x_i - x_j\|^2)\) corresponds to an infinite-dimensional feature space and measures similarity: nearby points have kernel value near 1, distant ones near 0. With an RBF kernel the SVM's prediction is a weighted vote of the support vectors, each weighted by its similarity to the new point, and \(\gamma\) sets how far each point's influence reaches: large \(\gamma\) gives wiggly, local boundaries (low bias, high variance), small \(\gamma\) smooth ones.

The price is computational. Kernel methods work with the \(n \times n\) matrix of pairwise kernel values, so training scales between \(n^2\) and \(n^3\). On the churn table, an RBF SVM took 0.4 s on 5,000 rows, 1.8 s on 10,000 and 8.7 s on 20,000 (about four times per doubling), and its AUC on 20,000 rows was only 0.744, well below logistic regression. It struggles with the one-hot categorical columns, the noise column and features that need different length scales. This is the typical picture since the mid-2010s: SVMs are excellent on small, clean, dense data sets with a few thousand rows (and were the state of the art for text classification and many vision tasks before deep learning), and are rarely used on large tables.

Talk track

"An SVM finds the maximum-margin boundary; only the support vectors matter, and C trades margin width against training errors. The kernel trick replaces dot products with a kernel such as RBF, which is equivalent to working in a huge feature space without building it. It is powerful on small data, but training is quadratic or worse in the number of rows, so for large tables boosting wins."

5.3k-nearest neighbours and the curse of dimensionality

k-NN is the simplest possible learner: it stores the training set and, for a new point, finds the \(k\) closest training points and lets them vote (or averages their targets). There is no training phase at all, which is why it is called lazy learning; all the work happens at prediction time. \(k\) is the regularisation dial. With \(k = 1\) the boundary passes between every pair of neighbouring points of different classes, fitting the training data perfectly (100 percent training accuracy on the moons data in Figure 5.3) with high variance. Larger \(k\) averages over more neighbours and smooths the boundary. On the churn table, k-NN with \(k = 100\) on standardised features reaches 0.796 test AUC.

k-NN depends entirely on the distance function, so feature scaling decides everything: an unscaled income in dollars would swamp a tenure in months. It also suffers most from the curse of dimensionality. In high dimensions, all points are roughly equally far from each other. For 1,000 random points in a unit cube, the ratio of the nearest to the farthest distance from a query point is 0.006 in 2 dimensions, 0.33 in 10, 0.70 in 100 and 0.89 in 1,000. When the nearest neighbour is almost as far as the farthest, "nearest" stops meaning "similar", and the neighbourhood needed to contain \(k\) points spans most of the range of every feature. Irrelevant features make this worse, because each adds distance that carries no signal.

In practice

Nearest-neighbour search is everywhere in modern systems, not as a classifier but as retrieval: recommendation ("customers similar to you bought"), deduplication, and the vector databases behind retrieval-augmented generation. These work in learned embedding spaces where distance is meaningful, and use approximate indexes (HNSW graphs, product quantisation) to search millions of vectors in milliseconds (GenAI).

5.4Naive Bayes: a generative model with a strong assumption

The other families model \(P(y \mid x)\) directly; they are discriminative. Naive Bayes is generative: it models how each class generates features, \(P(x \mid y)\), and the class frequencies \(P(y)\), then applies Bayes' rule, \(P(y \mid x) \propto P(y)\,P(x \mid y)\) (Mathematics 8). Modelling the full joint distribution of many features is hopeless, so it makes the "naive" assumption that features are independent given the class: \(P(x \mid y) = \prod_j P(x_j \mid y)\). Each factor is then a one-dimensional distribution that can be estimated by counting (categorical features), a Gaussian (numeric features), or word frequencies (multinomial naive Bayes for text).

The assumption is almost always false (tenure and contract type are correlated within churners), yet naive Bayes often classifies reasonably, because a ranking can be right even when the probabilities are wrong. The probabilities themselves are badly calibrated, pushed towards 0 and 1, because correlated features are counted as independent evidence several times. On the churn table it reaches 0.792 AUC but a log loss of 0.535, far worse than the 0.344 of logistic regression. Its strengths are speed (one pass over the data), tiny data requirements, and natural handling of very many sparse features, which made it the classic spam filter: with tens of thousands of word features and a few thousand emails, it was hard to beat in the early 2000s.

Pitfall

Zero counts. If a word never appeared in spam during training, \(P(\text{word} \mid \text{spam}) = 0\) and the product becomes zero for any email containing it, whatever else it says. Laplace (add-one) smoothing adds a small pseudo-count to every cell; scikit-learn's alpha=1.0 does exactly this.

Why it matters

The everyday question is "which model would you use and why?". The best answer names the inductive bias: linear models assume additive effects, trees assume thresholds and interactions, k-NN and kernels assume that similar inputs have similar outputs under a distance you must choose, naive Bayes assumes conditional independence. Then it names the practical constraints: data size, feature types, latency, explanation needs.

6Unsupervised learning: clustering and dimensionality reduction

Without labels there is no right answer to score against, only structure to find. Clustering groups similar rows; dimensionality reduction finds a few directions that summarise many correlated columns. Both are used to explore data, to build features for supervised models, and to compress. Each algorithm carries an assumption about what a "group" is, and choosing the algorithm means choosing that assumption.

6.1k-means: centres and the nearest-centre rule

A marketing team wants customer segments for different retention campaigns. k-means is the default first try. It represents each of \(k\) clusters by a centre and assigns every point to its nearest centre. The goal is to minimise the inertia, the sum of squared distances from each point to its centre. Lloyd's algorithm alternates two steps until nothing changes (Figure 6.1): assign every point to its nearest centre, then move every centre to the mean of its assigned points. Each step can only lower the inertia, so the algorithm always converges, usually in a handful of iterations; in the figure it falls from 2,631 to 809, 492, 330, 309 and 308.

The result depends on the start, because the inertia has many local minima. k-means++ initialisation (the default in scikit-learn) picks the first centre at random and each next one with probability proportional to its squared distance from the existing centres, which spreads them out; running the algorithm several times (n_init) and keeping the best adds safety. Choosing \(k\) is the harder question. The inertia always falls as \(k\) grows (1,470, 848, 308, 265, 230, 203 for \(k\) = 1 to 6 on this data), so it cannot choose \(k\) by itself; one looks for the "elbow" where the drop flattens (here clearly at 3), or uses the silhouette score, which compares each point's distance to its own cluster with its distance to the next one. In business, \(k\) is often set by how many campaigns the team can run.

k-means assumes clusters are round blobs of similar size, because "nearest centre" in Euclidean distance carves space into convex cells. It fails on elongated, curved or unequal clusters (Figure 6.2), is sensitive to feature scaling and outliers (a single far point drags a mean), and works only with numeric features where averages make sense. Its strengths are speed (linear in the number of points per iteration; mini-batch k-means handles millions) and simplicity. It is also used outside clustering: colour quantisation of images and vector quantisation in compression and in approximate nearest-neighbour indexes.

6.2Gaussian mixtures: soft, elliptical clusters

A Gaussian mixture model (GMM) assumes the data was generated by \(k\) Gaussian distributions, each with its own mean, covariance and weight, and fits all of them by maximum likelihood. Because each component has a full covariance matrix, clusters can be elongated and tilted ellipses. Because the model is probabilistic, each point gets a soft assignment: a probability of belonging to each cluster, which is more honest for points between clusters.

The fitting algorithm is expectation-maximisation (EM), a soft version of k-means. The E-step computes, for every point, the probability that each component generated it, given the current parameters. The M-step re-estimates each component's mean, covariance and weight from all points, weighted by those probabilities. Each iteration increases the likelihood, and like k-means it can converge to a local optimum. k-means is in fact the limit of a GMM with equal, spherical, shrinking covariances. On the stretched blobs of Figure 6.2, k-means cuts across the ellipses (adjusted Rand index 0.51 against the true groups) while the GMM recovers them exactly (1.00). The price is more parameters (a covariance matrix per cluster grows with the square of the number of features), sensitivity to initialisation, and the same convex-cluster assumption: on two moons the GMM does no better than k-means.

Interesting detail

Because a GMM is a full probability model, it can choose \(k\) with information criteria (BIC penalises the log-likelihood by the number of parameters), and it gives a density, so points with very low likelihood under all components are anomaly candidates. EM itself is a general recipe for fitting models with hidden variables; the Baum-Welch algorithm for hidden Markov models is EM too.

6.3DBSCAN: clusters as dense regions

DBSCAN defines a cluster not by a centre but by density: a cluster is a region where points are packed closely, separated from other clusters by sparse regions. It has two parameters: a radius \(\varepsilon\) and a minimum number of points. A point with at least that many neighbours within \(\varepsilon\) is a core point; core points within \(\varepsilon\) of each other are joined into one cluster, together with the border points they reach; everything else is noise. The number of clusters is not given in advance; it comes out of the data.

Because it follows density, DBSCAN finds clusters of any shape: on the two moons it recovers both (ARI 0.99) where k-means and the GMM cut them in half (0.47 and 0.48). It is robust to outliers, which it labels as noise rather than forcing them into a cluster; on the blobs with scattered points it marks 41 points as noise. Its weaknesses are the choice of \(\varepsilon\) (a k-distance plot helps), clusters of very different densities (one \(\varepsilon\) cannot fit both; HDBSCAN, which builds a hierarchy over all densities, fixes most of this), and high dimensions, where density loses meaning for the reasons of Section 5.3.

In practice

Clustering results are only as good as the features and scaling fed to them, and there is no ground truth to check them against. Teams judge segments by whether they are stable (do they reappear on another month's data?), interpretable (can the cluster be described in a sentence?) and actionable (does a different campaign per segment perform better in an A/B test?). For anomaly detection on tables, isolation forests (which isolate points with random splits; anomalies need few splits) are a common alternative to density methods.

6.4PCA: the directions that carry the variance

Many columns in a real table are correlated: rooms, bedrooms, households and population in the housing data all measure district size. Principal component analysis finds new axes, the principal components, ordered by how much of the data's variance lies along them. The first component is the direction of largest spread; the second is the direction of largest remaining spread orthogonal to the first; and so on (Figure 6.3, left). Projecting onto the first few components keeps most of the information in far fewer numbers.

Computationally, PCA centres the data and takes the singular value decomposition \(X = U S V^\top\): the rows of \(V^\top\) are the components and the squared singular values give the variance along each (Mathematics 4). Equivalently, the components are the eigenvectors of the covariance matrix. On the 8×8 handwritten digits (64 pixel features, 1,797 images), 31 components keep 90 percent of the variance and 40 keep 95 percent (Figure 6.3, right): the data really lives on a much lower-dimensional surface than 64 numbers suggest.

PCA is used to compress features before a model that suffers from many correlated inputs (k-NN, SVMs, unregularised regression), to remove noise by dropping small components, to visualise data in two dimensions, and to decorrelate inputs. It is linear and unsupervised: it keeps directions of high variance, which are not necessarily the directions that predict the label, so a low-variance feature that determines churn can be thrown away. It is also sensitive to scale (standardise first, unless all features share units), and its components are mixtures of all original features, which makes them harder to explain than the features themselves.

Pitfall

Reading clusters into t-SNE or UMAP plots. These non-linear methods are excellent for visualising high-dimensional data in 2-D, because they preserve local neighbourhoods. But distances between clusters, cluster sizes and densities in the plot are not meaningful, and the picture changes with the perplexity or neighbour parameter. Use them to look, not to measure, and never as features fitted on all data before a train/test split.

Talk track

"k-means assumes round clusters of similar size and minimises squared distance to centres; GMM fits ellipses with soft assignments via EM; DBSCAN finds dense regions of any shape and labels outliers as noise, without fixing k. PCA rotates the data onto orthogonal directions ordered by variance, computed with the SVD; it compresses well but ignores the label and only captures linear structure."

7Honest evaluation: splits, cross-validation and model selection

A model's score is only meaningful if it was measured on data that played no part in building the model, in conditions that imitate how the model will be used. Most failed ML projects did not pick the wrong algorithm; they measured the right one wrongly and believed it.

7.1Training, validation and test sets

Three jobs need three kinds of data. The training set fits the parameters. The validation set chooses among models and hyperparameters: tree depth, regularisation, which features, when to stop boosting. The test set estimates the final performance and is used once, at the end. The reason for the separation is that every decision taken while looking at a data set fits the model a little to that set. A validation score that guided fifty decisions is optimistic; a test score that was looked at once is not.

The split must imitate deployment. If the model will score next month's customers, the test set should be later months, not a random sample of the same months, because customer behaviour, prices and the product drift over time. If the model will score new customers, the same customer must not appear in both training and test. If several rows belong to one entity (transactions of one card, visits of one patient), split by entity. A random split on such data measures how well the model recognises entities it has already seen, which is not the question. The neural-network chapter treats the same rules for images and videos (Neural network training 2.3).

Pitfall

Re-using the test set. After the tenth "final" evaluation, the test set has become a validation set, and the reported number is optimistic. Keep a locked test set, or at least record how many times it has been used, and when in doubt collect a fresh one (next month's data is a natural fresh test set).

7.2Cross-validation and its variants

One validation split gives one noisy number. k-fold cross-validation splits the training data into \(k\) folds (usually 5 or 10), trains \(k\) models each validated on a different fold, and averages the scores (Figure 7.1). Every row is used for validation exactly once, and the spread of the fold scores shows how much the estimate depends on the particular split. On 4,000 churn rows, five folds gave AUCs of 0.798, 0.789, 0.782, 0.781 and 0.767: mean 0.784, standard deviation 0.010. Two models that differ by 0.003 on such data are indistinguishable.

The variants exist because rows are rarely independent. Stratified k-fold keeps the class proportions equal in every fold, which matters when positives are rare. Group k-fold keeps all rows of a group (a customer, household, store, patient) in the same fold. Time-series split always trains on the past and validates on the following period, with an expanding or sliding window; a gap between them avoids leakage through features that look back across the boundary. Leave-one-out (k = n) is nearly unbiased but expensive and high-variance; it is used only for tiny data sets.

7.3Hyperparameter search

Hyperparameters are chosen by trying configurations and comparing their cross-validated scores. Grid search tries every combination of a few values per hyperparameter. It is simple and exhaustive, but the cost multiplies with every new dimension, and it wastes trials: if only one of two hyperparameters matters, a 3×3 grid tests only three distinct values of the one that matters. Random search samples configurations at random from distributions and, with the same nine trials, tests nine distinct values of every hyperparameter (Figure 7.2). Bergstra and Bengio (2012) showed that random search finds models as good as grid search in a fraction of the trials, because in most problems only a few hyperparameters matter, and nobody knows in advance which.

Bayesian optimisation (for example Optuna's tree-structured Parzen estimator, or Gaussian-process methods) goes further: it builds a model of score versus configuration from the trials so far and proposes the next configuration where improvement is most likely. Successive halving and Hyperband save compute by giving many configurations a small budget (few trees, a data subset) and continuing only the best. In practice, for gradient boosting, a few dozen random or Optuna trials over learning rate, tree size, minimum leaf size, subsampling and regularisation, each with early stopping, capture most of the available gain.

The gain is usually modest compared with the gain from features and data. A 40-trial random search for LightGBM on 4,000 churn rows produced cross-validated AUCs from 0.732 (a bad configuration) to 0.796, with a median of 0.785; our hand-set configuration scored 0.784. The winner was a strongly regularised model (4 leaves, 100 trees), sensible for so little data, and it scored 0.808 on the test set when refitted on all 4,000 rows. Tuning bought about a point; going from 4,000 to 40,000 rows bought another point.

In practice

Search on a log scale for scale-like hyperparameters (learning rate, regularisation strength, C, gamma), fix the number of boosting rounds by early stopping rather than searching it, and spend the first hour on a sensible default and a strong validation scheme rather than on search. Record every trial; a search whose results are lost has to be run again.

7.4The optimism of picking the best, and nested cross-validation

When forty configurations are scored on the same folds and the best is reported, that best score is biased upwards: some of its advantage is luck in the particular folds, and the luck does not transfer. The more configurations are compared and the smaller the validation data, the larger the bias. This is the same effect as the test-set reuse of Section 7.1, now inside model selection.

The clean solution is nested cross-validation: an outer loop splits off a test fold, an inner cross-validation on the remaining data runs the whole search, the chosen configuration is refitted and scored on the outer fold. The average outer score estimates the performance of "the procedure of searching and then fitting", which is what will be deployed. It is expensive (inner search times outer folds), so in practice teams use a single held-out test set that the search never touches, which estimates the same thing with one outer fold.

When comparing two models, compare them on the same folds and look at the per-fold differences, not just the means: a model that wins on all five folds by 0.004 is more convincingly better than one that wins on average by 0.006 with two losses. For final numbers on a test set, a bootstrap over test rows gives a confidence interval; with 10,000 rows and 1,528 positives, an AUC is known to within about ±0.01 (Neural network training 7.6 treats test-set uncertainty in more depth, and 11.3 seed noise).

Talk track

"Train fits parameters, validation chooses hyperparameters, test estimates final performance once. I use cross-validation with folds that imitate deployment: stratified for imbalance, grouped by customer, or time-based. Hyperparameters go through random or Bayesian search with early stopping, and because picking the best of many is optimistic, the final number comes from a held-out test set or nested CV."

8Metrics: confusion matrices, ROC and PR curves, thresholds and imbalance

A classifier outputs a score; the business needs a decision. Metrics connect the two. The confusion matrix counts the four outcomes at one threshold; ROC and precision-recall curves summarise all thresholds; and the right threshold comes from the cost of each kind of error. Class imbalance changes which of these numbers can be trusted.

8.2ROC curves and AUC

Sweep the threshold from 1 down to 0 and plot recall (true positive rate) against the false positive rate at each step: that is the ROC curve (receiver operating characteristic, from radar engineering). It starts at (0, 0) with nobody flagged and ends at (1, 1) with everybody flagged. A random score follows the diagonal; a perfect one goes straight up to (0, 1). The area under the curve (ROC-AUC) summarises it in one number between 0.5 (random) and 1 (perfect).

The AUC has a concrete meaning worth remembering: it is the probability that a randomly chosen churner gets a higher score than a randomly chosen stayer. Our model's 0.818 means that in 82 percent of churner-stayer pairs, the churner is ranked higher. This makes AUC a pure measure of ranking: it ignores the threshold, it is unchanged by any monotone transformation of the scores (so it says nothing about calibration), and, because TPR is computed only among positives and FPR only among negatives, it does not depend on the class balance. That last property is both its strength and its trap.

8.3Precision-recall curves, and why ROC can look too good

The precision-recall curve plots precision against recall as the threshold sweeps; its area is reported as average precision (AP, also called PR-AUC). A random classifier has precision equal to the positive rate at every recall, so the baseline is a horizontal line at the prevalence, 0.153 for churn, not 0.5. Precision has false positives in its denominator, which are counted among the much larger negative class, so precision reacts to imbalance where the FPR does not.

Use Figure 8.2 to see the difference. Move the threshold and watch the red point travel along both curves and the confusion matrix change. Then switch the prevalence to 0.5 percent, a fraud-like rate, keeping exactly the same model scores but making churners thirty times rarer. The ROC curve and its AUC (0.818) do not move at all. The PR curve collapses: average precision falls from 0.471 to 0.038, and at threshold 0.3 precision falls from 47 percent to 2.4 percent. In a fraud setting, that means 41 false alarms for every real fraud the analysts look at. ROC-AUC says "this model ranks well"; PR-AUC says "but its flagged list is mostly noise at this base rate". Both are true, and only the second one describes the analysts' day.

The rule that follows: when positives are rare and the cost lies in reviewing flagged cases (fraud, defects, rare disease, security alerts), report PR-AUC or precision at a fixed recall, next to ROC-AUC. When classes are roughly balanced, or the question is purely about ranking, ROC-AUC is fine and has the advantage of being comparable across data sets with different base rates. In either case, the number that matters most is the one at the operating point: "at 60 percent recall, precision is 33 percent" is a statement a team can plan around.

Pitfall

Comparing PR-AUC across data sets or time periods with different base rates. A drop in average precision from one month to the next may simply mean that fewer customers churned that month. ROC-AUC is the stable number for tracking ranking quality over time; PR-AUC is the honest number for the current base rate.

8.4Choosing the threshold: costs, capacity and calibration

The default threshold of 0.5 has no special meaning; it minimises errors only if both kinds of error cost the same and the probabilities are calibrated. The right threshold comes from the decision. Suppose a retention call costs $5 and one in three churners who receive a call stays, worth $100 in margin each, so reaching a churner is worth $30 on average. Flagging everyone above threshold \(t\) is worth \(30 \cdot TP(t) - 5 \cdot (TP(t) + FP(t))\). On the test set this value peaks at a threshold of about 0.15 ($17,330 per 10,000 customers) and is only $6,870 at 0.5. With calibrated probabilities the rule is direct: call a customer when \(p \times 30 > 5\), that is when \(p > 0.17\), very close to the empirical optimum.

Often the constraint is capacity rather than cost: the team can make 1,500 calls a month. Then the threshold is whatever flags 1,500 customers, here about 0.3, and the metric that matters is precision at that volume (47 percent). Other settings fix recall instead ("catch 90 percent of fraud") and ask for the best precision there.

Threshold rules based on probabilities need calibrated probabilities: among customers scored 0.3, about 30 percent should leave. Logistic regression and LightGBM trained on log loss are close (expected calibration error 0.012 and 0.007 on the churn test set). Naive Bayes is far off (0.188: the customers it scores between 0.25 and 0.35 actually churn at 9 percent), random forests pull probabilities towards the middle, and class weighting breaks calibration on purpose (Section 8.5). Calibration can be checked with a reliability diagram and repaired with Platt scaling or isotonic regression fitted on held-out data, as described in Neural network training 8.1 and 8.2.

Talk track

"The model gives a score; the threshold is a business decision. I pick it from the cost of false positives and false negatives, or from capacity, such as how many cases a team can review. If the probabilities are calibrated, the cost-optimal threshold is the cost ratio. ROC-AUC tells me how well the model ranks; the confusion matrix at the chosen threshold tells me what will actually happen."

8.5Class imbalance: what helps and what only seems to

Imbalance is the normal state of the problems ML is used for: churn at 15 percent, conversion at 3 percent, fraud at 0.1 percent, defects at parts per million. The usual worry is that the model "ignores the minority class". On the rare version of the churn table (1.3 percent positives, 100,000 customers), a plain LightGBM model ranks well (AUC 0.806) but its probabilities are honest about how rare churn is: none reaches 0.5, so at the default threshold it flags 3 customers and catches none. That looks like failure, but it is a threshold problem, not a learning problem.

The common remedies act at different places. Class weights (class_weight="balanced", scale_pos_weight) multiply the loss of positive rows. Trained with a weight of about 77, the same model flags 5,480 customers at 0.5 and catches 62 percent of churners. But its AUC is not better (0.797 against 0.806) and its probabilities are now wrong by design: the mean predicted probability is 0.25 for a 1.3 percent problem. On the original churn table, class weighting raises the expected calibration error of LightGBM from 0.007 to 0.232. Weighting shifted the scores; moving the threshold of the plain model would have given the same trade-off and kept the probabilities usable. Resampling (undersampling the majority, oversampling the minority, or synthesising minority points with SMOTE) has the same effect plus the risk of overfitting duplicated or interpolated points; SMOTE in particular rarely helps strong models such as gradient boosting.

What actually helps with rare positives is more positive examples, features that separate them, a metric that measures the minority class (PR-AUC, recall at fixed precision), stratified folds so every fold has positives, and a threshold chosen for the decision. Weighting or undersampling earns its place when the model has limited capacity and would otherwise spend it on the majority, or when undersampling a huge majority saves training time (then correct the probabilities back afterwards). The deep-learning view of the same problem, including focal loss, is in Neural network training 6.4.

Pitfall

Resampling before splitting. Oversampling or SMOTE applied to the whole data set puts copies or interpolations of the same positive row into both training and validation folds, and the validation score measures memorisation. Resample inside the training fold only (imbalanced-learn's Pipeline does this), and always evaluate on data with the true class balance.

8.6Regression metrics

For the house-price model, the errors are numbers, and the metrics differ in how they weigh them. MAE (mean absolute error) is the average size of the miss in dollars, easy to explain and robust to a few huge misses. RMSE (root mean squared error) squares the misses before averaging, so large errors dominate; it is the metric that least squares optimises. MAPE (mean absolute percentage error) expresses the miss relative to the true value, which suits prices spanning a wide range, but explodes when true values are near zero and favours under-prediction. R² is the fraction of variance explained relative to predicting the mean: 0 for the mean, 1 for perfect, and negative for a model worse than the mean.

9Features, leakage and interpretability

On tabular data, features matter more than algorithms, and the most dangerous features are the ones that are too good. This chapter covers how features are built, how information from the future or from the test set leaks into them, how to build pipelines that prevent it, and how to explain what a model has learned.

9.1Feature engineering for tables

Raw business data rarely arrives as one row per customer. It arrives as event logs: logins, payments, support tickets, plan changes, each with a timestamp. A model needs one row per customer at the moment of prediction, so most feature engineering is aggregation over time windows: support calls in the last 7, 30 and 90 days; days since the last login; the number of failed payments this quarter; the change in usage between the last month and the three before ("is usage falling?"). Ratios and differences add more: charges per product, share of the bill spent on extras, price paid relative to the median for the same plan. Recency, frequency and monetary value (RFM) is the classic trio for customer data.

Categorical columns need an encoding. One-hot works for a few levels. For high-cardinality columns (postcode, merchant, device model, thousands of levels), one-hot is too wide and sparse; options are frequency encoding, grouping rare levels into "other", native categorical support in LightGBM and CatBoost, learned embeddings, or target encoding: replace each level with the average label of training rows with that level, shrunk towards the global mean for rare levels. Target encoding is powerful and dangerous; Section 9.2 shows why. Missing values can carry information ("no payment method on file"), so a missing-indicator column often helps; gradient-boosting libraries learn a default branch for missing values automatically.

How much engineering a model needs depends on the family. Linear models need the shapes handed to them (Section 3.4). Tree ensembles find thresholds and interactions themselves, but they cannot aggregate across rows: a tree sees one customer's row and cannot count that customer's events unless a feature does. That is why the aggregation step matters for every family, and why it is where domain knowledge pays off most.

In practice

Larger organisations keep features in a feature store, which computes each feature once, stores its values with timestamps, and serves the same definition to training ("what was this value on 1 March?") and to production ("what is it now?"). Its two jobs are reuse and preventing training-serving skew, the bug where a feature is computed slightly differently in the training notebook and in the production service, so the deployed model sees inputs it was never trained on.

9.2Leakage: when the model sees the answer

Leakage is information in the training features that would not be available at prediction time, or information from the evaluation data that influenced training. It produces models that look excellent offline and fail in production, and it is the most common reason that a "great" model disappoints. There are three main forms.

Target leakage comes from features that are consequences of the label. In our churn data, the retention team sends an offer to customers after they ask to cancel; 62 percent of churners received one and 3 percent of stayers. Adding a column retention_offer_sent lifts the test AUC from 0.818 to 0.909 and the PR-AUC from 0.476 to 0.758, an apparently huge improvement. But at prediction time, before anyone has asked to cancel, the flag is zero for everybody, and the model's real performance is back at 0.817. The 0.909 described a world that does not exist (Figure 9.1). Real examples are everywhere: "account closed date", a fraud flag set by the investigation, a diagnosis code entered after the test result, the "number of collection calls" for predicting default.

Train-test contamination happens when preprocessing or selection uses all the data before the split. The striking demonstration: take 100 rows of pure noise, 5,000 random features and random labels. Select the 20 features most correlated with the label on all 100 rows, then cross-validate a logistic regression on them: 85 percent accuracy, on data with no signal at all. Put the same selection inside the cross-validation pipeline, so it is redone on each training fold, and the accuracy is 46 percent, as it should be. The selection had seen the validation labels. The same happens, more subtly, with scaling, imputation, PCA or oversampling fitted on all data, and with duplicates or near-duplicates across the split.

Temporal and group leakage happens when the split does not respect time or entities: training on customers' future months to predict their past, or having the same customer in training and test so that the model recognises the customer rather than learning the pattern (Section 7.1). Target encoding is a classic trap that combines these: encoding a column by the average label of the same rows the model trains on lets each row see its own label. On a random 20,000-level ID with no signal, the naive encoding alone scores a training AUC of 0.928 and a test AUC of 0.508. Correct target encoding uses out-of-fold averages (scikit-learn's TargetEncoder does this internally) or CatBoost's ordered statistics.

Pitfall

The tell-tale signs of leakage: a validation score far above what similar projects achieve, one feature with overwhelming importance, a feature whose meaning involves the outcome ("after", "result", "status", "closed"), and a large drop between offline evaluation and the first production weeks. When a model is surprisingly good, look for the leak before celebrating. The neural-network view of leakage through near-duplicate images and sequences is in Neural network training 9.1.

9.3Pipelines: making the right thing the easy thing

The practical defence against contamination is to put every step that learns from data (imputation, scaling, encoding, feature selection, resampling, the model) into one pipeline object, and to pass that object to cross-validation and search. Then every fold refits every step on its own training part only, and the production model applies exactly the transformations it was trained with. A pipeline is a single artefact to version, test and deploy.

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, TargetEncoder, StandardScaler
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import TimeSeriesSplit, cross_val_score

pre = ColumnTransformer([
    ("num", SimpleImputer(strategy="median", add_indicator=True), numeric_cols),
    ("low", OneHotEncoder(handle_unknown="ignore", min_frequency=50), ["contract", "payment"]),
    ("high", TargetEncoder(target_type="binary"), ["postcode"]),   # cross-fitted internally

"Leakage is any information at training time that the model will not have at prediction time. I guard against it by fixing a prediction time and building features only from data before it, splitting by time and by entity, and putting all preprocessing inside a pipeline that is refitted within each cross-validation fold. A suspiciously good score is a leakage alarm."

9.4Feature importance: impurity versus permutation

Once a model works, people ask which features drive it. Tree libraries report impurity importance (also called gain or mean decrease in impurity): the total impurity reduction from all splits on a feature, summed over the trees. It is free to compute but measured on training data, and it is biased towards features with many possible split points. Figure 9.2 shows the consequence on the churn table: a random forest ranks account_hash, a column of pure random numbers, as the third most important feature (0.133, ahead of age and login recency). Deep trees use its many unique values to split off individual training customers, which reduces training impurity and means nothing.

Permutation importance asks a better question: how much does the test score drop when one feature's values are shuffled across rows, breaking its link to the label? On the same model, shuffling contract = monthly costs 0.066 AUC, tenure 0.052, monthly charges 0.042, and account_hash −0.001: nothing. It works for any model and measures what matters on new data. Its weakness is correlated features: shuffling one of two near-duplicates costs little because the other still carries the information, so both look unimportant, and shuffling creates unrealistic rows (a 20-year-old with 70 months of tenure). Dropping the feature and retraining (drop-column importance) answers the question cleanly but costs one training run per feature.

Pitfall

Reading importance as causation. "Support calls are important" means the model uses them to predict churn, not that reducing calls would reduce churn: unhappy customers call, and the calls are a symptom. Turning a predictive model into a decision about interventions needs causal reasoning or an experiment (an A/B test of the retention offer), not a feature-importance chart.

9.5SHAP: explaining one prediction

Global importance says what the model uses on average. The retention agent on the phone needs something else: why this customer? SHAP (SHapley Additive exPlanations, Lundberg and Lee 2017) splits one prediction into contributions per feature that add up exactly: prediction = base value + sum of contributions. The base value is the model's average output; each contribution is the feature's Shapley value, a concept from cooperative game theory. Think of the features as players who together produce the prediction. A feature's Shapley value is its average marginal contribution, the change in the prediction when the feature is added, averaged over all orders in which the features could be added. It is the only attribution that satisfies a few fairness properties: contributions sum to the prediction, a feature that never changes the output gets zero, and identical features get equal shares.

Exact Shapley values need every subset of features, which is exponential, but for tree ensembles the TreeSHAP algorithm computes them exactly in polynomial time by walking the trees, which is why SHAP and gradient boosting are a standard pair. For other models, KernelSHAP approximates them by sampling. Figure 9.3 shows one high-risk customer. The model's average output is −2.26 in log-odds (log-odds are what the model adds up; averaged log-odds correspond to 9.5 percent, below the 15.3 percent churn rate, because averaging log-odds is not averaging probabilities). Monthly charges of $127 add +1.31, the monthly contract +1.15, manual payment +0.30, 13 months of tenure +0.15, and so on, ending at +0.72 log-odds, a 67 percent churn probability. An agent can read it as "high bill without a contract, manual payment": a reason, and a hint for the offer.

Aggregating SHAP values over many customers gives global views. The mean absolute SHAP value ranks features (contract 0.85, tenure 0.39, monthly charges 0.26, login recency 0.24, products 0.23, and the random hash last at 0.04), and plotting a feature's SHAP value against the feature shows the shape the model learned. In tab 2, the model has recovered the true tenure effect from the data: strongly positive for the first months, fading through the first year, flat after two years.

Pitfall

SHAP explains the model, not the world. It inherits every flaw of the model: the random hash still gets small non-zero contributions because the boosted trees used it a little, and with correlated features the credit is split between them in ways that depend on the explainer's assumptions. A large SHAP value is not a causal effect, and explanations of a leaky model will confidently point at the leak.

Talk track

"SHAP attributes one prediction to the features with Shapley values from game theory: each feature gets its average marginal contribution over all orders of adding features, and the contributions add up exactly to the prediction minus the average. TreeSHAP computes them exactly and fast for tree ensembles. I use it for per-case reasons and, aggregated, for global importance and dependence plots, while remembering that it explains the model, not causality."

10Putting it together: the churn project end to end

The pieces of this chapter form one recipe that applies, with small changes, to churn, fraud, credit risk, demand and predictive maintenance. This chapter walks through it once and ends with where classical ML stops and other tools take over.

10.1The recipe, and what each step bought

Define the decision first: call up to 1,500 customers a month, predicting churn in the next 30 days from data available on the first of the month. Build one row per customer per month with features from the preceding 90 days, and split by time, keeping the latest months as the test set. Fit a regularised logistic regression as the baseline (0.806 AUC) and look at its coefficients for data bugs. Fit gradient-boosted trees with early stopping (0.818), compare on the same folds, and look at a learning curve to decide whether more history would help (here it is still rising slowly, 0.814 at 20,000 rows and 0.817 at 40,000, so more history would buy little). Check calibration (expected calibration error 0.007, no correction needed). Choose the threshold from capacity: about 0.3 flags 1,574 customers with 47 percent precision and 48 percent recall. Attach SHAP reasons to each flagged customer for the agents. Measure the real effect with a holdout group that is scored but not called, because the model predicts churn, not whether a call prevents it.

The same recipe predicts camera calibration failures at the end of a production line. 10.2After deployment, and where classical ML stops

A deployed model degrades as the world changes. Data drift is a change in the inputs (a new price plan shifts monthly charges), concept drift a change in the relationship between inputs and label (a competitor's offer makes long-tenure customers leave too). Monitoring compares feature distributions against training (population stability index, Kolmogorov-Smirnov tests), tracks the score distribution and the flag rate, and, once labels arrive 30 days later, the actual precision and recall. Retraining on a schedule (monthly here) with the same pipeline and an automatic comparison against the current model handles slow drift; a sudden change needs investigation first. The neural-network chapter covers the production loop, shadow mode and drift in more depth (Neural network training 14.3).

Classical ML is the right tool when the data is a table of meaningful columns, the data set is thousands to millions of rows, latency and cost matter, and decisions need explanations. Deep learning takes over when the raw input is images, audio, text or long event sequences, where the features themselves must be learned (Deep learning 1.3); and combinations are common: an embedding from a text or image model becomes a column in a gradient-boosted model. For many teams the most valuable skill is not choosing among the families but setting up the problem so that any of them can be measured honestly.

Talk track

"I start from the decision and the prediction time, build point-in-time features, split by time, fit a logistic baseline and then gradient boosting with early stopping, choose the threshold from cost or capacity, explain cases with SHAP, and measure impact with a holdout. After launch I monitor input drift, score distribution and, once labels arrive, precision and recall, and retrain on a schedule with the same pipeline."

QSelf-check questions

Q.1Core questions

What is the difference between supervised, unsupervised, self-supervised and reinforcement learning?Basic

Supervised learning has a label for every training example and learns to predict it (classification or regression). Unsupervised learning has no labels and looks for structure such as clusters or low-dimensional directions. Self-supervised learning creates labels from the data itself, for example by masking part of the input and predicting it, and is used to pretrain representations. Reinforcement learning has no labels but a reward for actions in an environment, often delayed, and learns a policy that maximises total reward.

Explain the bias-variance trade-off.Basic

Expected squared test error splits into bias squared (how far the average model over many training sets is from the truth), variance (how much the model changes from one training set to another) and irreducible noise. Flexible models have low bias and high variance; rigid ones the opposite. Total error is minimised at an intermediate flexibility, which is chosen by regularisation and validated on held-out data. In the polynomial example, degree 3 has total 0.110 against degree 1 at 0.195 (bias) and degree 12 at 3.27 (variance).

How do you detect and fix overfitting and underfitting?Basic

Compare training and validation error. Overfitting: low training error, much higher validation error, a gap that shrinks with more data; fix with more data, stronger regularisation, simpler models, early stopping or averaging. Underfitting: both errors high and close; fix with more flexible models, better features or less regularisation. A learning curve over training-set size shows which case you are in.

What is the difference between L1 and L2 regularisation?Basic

L2 (ridge) penalises the sum of squared weights and shrinks all weights smoothly; it handles correlated features by sharing weight. L1 (lasso) penalises the sum of absolute weights and sets some weights exactly to zero, performing feature selection, because the L1 constraint region has corners on the axes where the loss contours tend to touch it. Elastic net combines both. Both need standardised features.

Why does linear regression use squared error? How does that connect to maximum likelihood?Intermediate

If the targets are the linear function plus independent Gaussian noise of constant variance, the log-likelihood of the data is a constant minus the sum of squared residuals divided by twice the variance. Maximising likelihood is therefore minimising squared error. Other noise assumptions give other losses: Laplace noise gives absolute error, Bernoulli labels give log loss (logistic regression), Poisson counts give Poisson regression.

How does logistic regression work and how do you interpret its coefficients?Basic

It computes a linear score, the log-odds, and passes it through the sigmoid to get a probability. It is trained by minimising log loss, the negative Bernoulli log-likelihood, which is convex. A coefficient \(w_j\) is the change in log-odds per unit of feature \(j\), so \(e^{w_j}\) is the odds ratio: the factor by which the odds of the positive class multiply. Coefficients are comparable only for standardised features and can be unstable when features are correlated.

Why can't you use linear regression for classification?Basic

You can fit it to 0/1 labels, but the outputs are not probabilities (they go below 0 and above 1), squared error penalises confidently correct predictions far from the boundary, and a few extreme points can move the boundary a lot. Logistic regression fixes all three by modelling the log-odds and using log loss.

How does a decision tree choose its splits?Basic

Greedily: at each node it evaluates every feature and every threshold and picks the split that maximises the reduction in impurity (Gini or entropy for classification, variance for regression), weighted by the sizes of the children. It repeats recursively until a stopping rule (maximum depth, minimum samples per leaf, minimum gain). Example: splitting monthly customers at tenure 8.5 reduces Gini from 0.359 to 0.346.

What is the difference between bagging and boosting?Intermediate

Bagging trains many models independently on bootstrap samples and averages them; it reduces variance and suits high-variance base models such as deep trees (random forest). Boosting trains models sequentially, each fitting the errors (gradients) of the current ensemble, and adds them with a small learning rate; it reduces bias and, with shrinkage and subsampling, controls variance. Bagging parallelises trivially and rarely overfits with more trees; boosting needs early stopping.

How does gradient boosting work?Intermediate

Start with a constant prediction. At each round compute, for every training row, the negative gradient of the loss with respect to the current prediction (for squared error, the residual; for log loss, label minus probability). Fit a small regression tree to these pseudo-residuals, set its leaf values to reduce the loss, and add it scaled by the learning rate. Repeat until the validation loss stops improving. It is gradient descent in function space.

What did XGBoost, LightGBM and CatBoost add to gradient boosting?Intermediate

XGBoost: second-order (gradient and Hessian) split gains and leaf values, explicit L1/L2 regularisation of leaves, sparsity-aware handling of missing values, parallel and later histogram-based split finding. LightGBM: histogram binning, leaf-wise tree growth, gradient-based one-side sampling and exclusive feature bundling for speed on large data. CatBoost: ordered target statistics for categorical features and ordered boosting to avoid target leakage, plus symmetric trees. Results are usually within a few tenths of a point of each other.

Why do tree ensembles usually beat neural networks on tabular data?Intermediate

Tabular features are heterogeneous, often irrelevant, and have sharp thresholds and interactions. Trees are invariant to monotone transformations, ignore features they never split on, and model thresholds naturally; neural networks are biased towards smooth functions, are hurt more by uninformative features and need careful preprocessing. Benchmarks (Grinsztajn et al., 2022) confirm this on medium-sized data. Trees are also cheaper to train and tune. Neural networks win when inputs are images, text, audio or sequences.

Explain SVMs and the kernel trick.Intermediate

An SVM finds the separating hyperplane with the largest margin to the nearest points, the support vectors; the soft-margin version allows violations with hinge loss, weighted by C. Its optimisation and predictions depend on the data only through dot products, so replacing them with a kernel function (polynomial, RBF) is equivalent to working in a high- or infinite-dimensional feature space without computing it. Training scales roughly quadratically or worse with the number of rows.

What do C and gamma control in an RBF SVM?Intermediate

C is the penalty for margin violations: large C fits the training data closely (narrow margin, low bias, high variance), small C allows more violations (wider margin, more regularisation). Gamma is the inverse width of the RBF kernel: large gamma makes each support vector's influence local, giving wiggly boundaries and overfitting; small gamma gives smooth, nearly linear boundaries. They are tuned together on a log grid.

How does k-NN work, and how do you choose k?Basic

It stores the training data and predicts by majority vote (or average) of the k nearest training points under a distance metric, usually after standardising features. Small k gives low bias and high variance (k = 1 fits training data perfectly); large k smooths the boundary. k is chosen by cross-validation. Prediction is slow without an index, and performance degrades in high dimensions.

What is the curse of dimensionality?Intermediate

As dimensions grow, data becomes sparse and distances concentrate: the nearest and farthest neighbours are almost equally far (ratio 0.006 in 2-D, 0.89 in 1,000-D for uniform points), so similarity-based methods lose meaning, and the amount of data needed to cover the space grows exponentially. Remedies are feature selection, dimensionality reduction, learned embeddings, and models that do not rely on raw distances, such as trees.

Why is naive Bayes "naive", and why does it still work?Basic

It assumes features are conditionally independent given the class, so the class-conditional likelihood factorises into one-dimensional terms. The assumption is usually false, so its probabilities are poorly calibrated (overconfident), but the ranking of classes is often still right, and it needs very little data and one pass to train. It works well for text with many sparse word features. Use Laplace smoothing to avoid zero probabilities.

Explain the k-means algorithm and its limitations.Basic

Initialise k centres (k-means++), assign each point to the nearest centre, move each centre to the mean of its points, and repeat until assignments stop changing; this monotonically decreases the within-cluster sum of squares and converges to a local minimum. Limitations: k must be chosen, clusters are assumed round and of similar size, results depend on initialisation and scaling, outliers pull the means, and it needs numeric features.

When would you use DBSCAN or a Gaussian mixture instead of k-means?Intermediate

A GMM when clusters are elliptical or of different sizes and you want soft assignments or a density (it fits full covariances by EM). DBSCAN when clusters have arbitrary shapes, you do not know their number, and you want outliers labelled as noise; it needs a sensible radius and struggles with clusters of very different density (HDBSCAN helps). k-means when you want something fast and simple on roughly spherical groups.

What does PCA do and how is it computed?Basic

It finds orthogonal directions ordered by the variance of the data along them and projects the data onto the first few, maximising retained variance for a given number of dimensions. Computed from the SVD of the centred (usually standardised) data matrix, or equivalently the eigenvectors of the covariance matrix. The explained-variance ratio of each component guides how many to keep. It is linear and ignores the labels.

Explain k-fold cross-validation and when you would use group or time-series splits.Basic

Split the data into k folds, train on k−1 and validate on the remaining one, k times, and average the scores; this uses all data for validation once and shows the spread. Use stratified folds for imbalanced classes, group folds when several rows belong to one entity (customer, patient) so it never appears on both sides, and time-series splits when the model will predict the future, so validation is always after training.

Grid search versus random search versus Bayesian optimisation?Intermediate

Grid search tries all combinations of fixed values; cost explodes with dimensions and it tests few values of each parameter. Random search samples configurations and covers each important parameter more densely for the same budget (Bergstra and Bengio 2012). Bayesian optimisation (e.g. Optuna's TPE) models score versus configuration and proposes promising points, using fewer trials. Successive halving or Hyperband prune bad configurations early. Use early stopping for boosting rounds rather than searching them.

Explain precision, recall, F1 and when accuracy is misleading.Basic

Precision is the share of flagged cases that are truly positive; recall is the share of positives that are flagged; F1 is their harmonic mean. Accuracy counts all correct decisions and is dominated by the majority class: on churn with 15.3 percent positives, predicting "stays" for everyone gives 84.7 percent accuracy and catches nobody, higher than a useful model at threshold 0.3 (83.7 percent).

What is ROC-AUC and what does it measure?Basic

The area under the curve of true positive rate versus false positive rate over all thresholds. It equals the probability that a random positive is scored above a random negative, so it measures ranking quality, independent of threshold, of monotone transformations of the scores and of class balance. 0.5 is random, 1.0 perfect.

When would you prefer PR-AUC over ROC-AUC?Intermediate

When positives are rare and the cost lies in false alarms among the flagged cases, such as fraud, defects or rare disease. ROC-AUC uses the false positive rate, which stays small when negatives are abundant, so it can look excellent while most flagged cases are false. PR-AUC uses precision, which reflects the base rate: the same churn model has ROC-AUC 0.818 at 15 percent and at 0.5 percent prevalence, while PR-AUC falls from 0.47 to 0.04.

How do you choose a classification threshold?Intermediate

From the decision: minimise expected cost using the costs of false positives and false negatives (with calibrated probabilities, flag when \(p > c_{FP}/(c_{FP}+c_{FN})\)), or meet a capacity constraint (top N cases per day), or a required recall or precision. Choose it on validation data, not test data. 0.5 is only optimal for equal costs and calibrated probabilities.

How do you handle class imbalance?Intermediate

First use the right metric (PR-AUC, recall at fixed precision), stratified folds and a decision-based threshold; often that is enough, because a good model ranks rare positives well and the threshold does the rest. Class weights or resampling change the scores and can help weak or capacity-limited models, but they do not usually improve ranking for gradient boosting and they destroy calibration (on the churn data ECE went from 0.007 to 0.232). Resample only inside training folds. The best fix is more positive examples and better features.

What is data leakage? Give examples.Basic

Information available during training that will not be available at prediction time, or validation information that influenced training. Examples: a feature caused by the outcome (a retention offer sent after the cancellation request: AUC 0.909 offline, 0.817 real), preprocessing or feature selection fitted on all data before CV (85 percent accuracy on pure noise), target encoding without out-of-fold statistics, random splits on time series, and the same customer in train and test.

How does feature importance differ between impurity-based and permutation methods?Intermediate

Impurity importance sums split gains on the training data; it is free but biased towards high-cardinality and continuous features and can rank noise highly (a random ID column ranked third in the churn forest). Permutation importance measures the drop in a held-out score when a feature is shuffled; it reflects generalisation and works for any model, but it is diluted for correlated features and evaluates on unrealistic rows.

What are SHAP values?Intermediate

Per-prediction feature attributions based on Shapley values: each feature receives its average marginal contribution to the prediction over all orders of adding features, and the contributions sum exactly to the prediction minus the base value. TreeSHAP computes them exactly in polynomial time for tree ensembles. Aggregated, they give global importance and dependence plots. They explain the model, not causality, and split credit between correlated features in an assumption-dependent way.

What is model calibration and how do you fix it?Intermediate

A model is calibrated if, among cases it scores p, a fraction p are positive. Check with a reliability diagram or expected calibration error on held-out data. Logistic regression and boosting trained on log loss are usually close; naive Bayes, SVM scores, random forests and class-weighted models are not. Fix with Platt scaling (logistic on the scores) or isotonic regression, fitted on data not used for training.

Walk me through how you would build a churn model.Advanced

Define the decision (who to contact, capacity, cost per contact, value of a save), the prediction time and the label window. Build point-in-time features from the preceding months (usage trends, support contacts, billing, contract), one row per customer per month. Split by time, group by customer. Fit a logistic baseline, then LightGBM with early stopping; compare with cross-validated PR-AUC and ROC-AUC. Check calibration, choose the threshold from capacity or cost, add SHAP reasons. Measure impact with a scored-but-not-contacted holdout, then monitor drift and retrain monthly with the same pipeline. Expect most gains from features and the decision, not the algorithm.

How would you evaluate a fraud model with 0.1 percent positives?Advanced

Split by time (fraud patterns change) and, where relevant, by account. Report precision-recall curves and precision at the analysts' review capacity or at a required recall, plus ROC-AUC for stability over time; never accuracy. Use enough months to have hundreds of positives in test and give confidence intervals. Account for label delay (chargebacks arrive weeks later) and for feedback: blocked transactions never get a label. Translate the operating point into money: fraud caught versus customers wrongly blocked.

Q.2Why and what if

Why does an unlimited decision tree score 1.000 training AUC but 0.602 test AUC on the churn data?Why

It keeps splitting until every leaf is pure, so it memorises each training customer, including the random part of their outcome. Those accidents do not repeat on new customers, so most leaves predict noise. Limiting depth and leaf size (0.791) or averaging many trees (0.816) removes most of that variance.

Why does adding more trees to a random forest not cause overfitting, while adding more rounds to boosting does?Why

Forest trees are independent and averaged, so more trees only reduce the variance term towards \(\rho\sigma^2\); the ensemble converges. Boosting rounds are sequential corrections that keep reducing training loss, eventually by fitting noise (training RMSE fell below the noise level after 100 stumps), so the number of rounds is a capacity control and needs early stopping.

Why does lasso pick only one of two strongly correlated features?Why

For two near-identical features, putting all weight on one costs less L1 penalty than splitting it only when the loss is identical; the L1 geometry favours corners, so the solution sits where one weight is zero. Which one is chosen can flip with small data changes. Ridge, whose penalty prefers spreading weight, keeps both; elastic net is the compromise when grouped selection is wanted.

Why is ROC-AUC unchanged when positives become rarer, while precision collapses?Why

TPR is computed only within positives and FPR only within negatives, so re-weighting the classes changes neither. Precision mixes the classes: at a fixed FPR, the number of false positives grows with the number of negatives, so the share of true positives among flagged cases falls. At 0.5 percent prevalence the churn model's precision at threshold 0.3 is 2.4 percent.

Why can a random ID column get high impurity importance?Why

It has many unique values, so deep trees can always find thresholds on it that separate a few training rows and reduce training impurity. Impurity importance adds up those reductions on the training data, rewarding memorisation. Permutation importance on held-out data shows the column is worthless (−0.001 AUC).

Why does the k-means objective always decrease, and why can it still give a bad answer?Why

The assignment step chooses, for fixed centres, the assignment with the lowest sum of squares, and the update step chooses, for fixed assignments, the centres with the lowest sum of squares (the means). Neither can increase it, and there are finitely many assignments, so it converges. But it converges to a local minimum that depends on the start, and its objective prefers round equal clusters even when the true groups are not.

Why is selecting features on the full data set before cross-validation a problem, if the model itself is trained correctly inside the folds?Why

The selection used the labels of the rows that later serve as validation, so it picked features that happen to correlate with those particular labels. Validation then measures the luck of the selection. On pure noise with 5,000 features this gave 85 percent accuracy; with selection inside each fold it gave 46 percent.

Why does logistic regression tend to produce calibrated probabilities while naive Bayes does not?Why

Logistic regression directly minimises log loss, a proper scoring rule, on the training labels; at the optimum with an intercept, the average predicted probability equals the observed rate, and per-group calibration follows when the model is roughly right. Naive Bayes multiplies per-feature likelihoods as if they were independent, so correlated evidence is counted several times and probabilities are pushed towards 0 and 1 (ECE 0.188 on churn).

What if you train on log(price) but the business measures error in dollars?What if

The model will minimise relative error, which is good for cheap houses and worse for expensive ones, so dollar RMSE may get slightly worse (LightGBM: $43.0k to $44.1k) while MAPE improves (15.7 to 14.5 percent). Exponentiating a mean log prediction also gives the median, not the mean, which biases dollar predictions low unless corrected. Choose the target to match the business metric.

What if your validation AUC is 0.97 on a problem where published results are around 0.80?What if

Suspect leakage first: look for a feature with dominant importance, check whether each feature's value would be known at prediction time, check the split for shared entities or time overlap, and check preprocessing for steps fitted on all data. Then re-run with a strict time-based holdout. Only after that consider that the model is genuinely better.

What if the learning curve shows training and validation scores both at 0.80, flat, and the target is 0.85?What if

The model is bias-limited: more data of the same kind will not help. Add information (new features, new data sources), use a more flexible model or reduce regularisation, or reconsider whether 0.85 is achievable at all, since the noise in the labels may set the ceiling. On the synthetic churn data, the ceiling was 0.822.

What if you use class_weight="balanced" and then use the predicted probabilities to compute expected revenue?What if

The revenue estimate will be badly wrong, because class weighting inflates positive-class probabilities: on the rare churn data the mean score rose from 0.013 to 0.25 for a 1.3 percent problem. Either train without weights and move the threshold, or recalibrate the weighted model on held-out data with the true class balance before using its probabilities.

What if two features are perfect copies of each other? What happens to permutation importance and SHAP?What if

Permutation importance of each will be near zero, because shuffling one leaves the other intact, so the model barely loses anything; the pair looks unimportant although together they matter. SHAP will split the credit between them, roughly equally for a symmetric model, but how depends on which copy the trees happened to use. Group correlated features before computing importance, or drop one copy.

What if you scale the features with StandardScaler fitted on the whole data set before splitting?What if

It is a mild form of contamination: the means and variances include the test rows. For large, stationary data the effect on scores is usually tiny, but it sets a dangerous habit and can matter with small data, time drift, or steps that learn more (target encoding, feature selection, imputation by model, oversampling). Put every fitted step in a pipeline so the question never arises.

What if your churn model is good, but calling the flagged customers does not reduce churn?What if

The model predicts who will leave, not who can be persuaded to stay. Some flagged customers leave regardless (lost causes), some would have stayed anyway. Measure the effect of the call with a randomised holdout of flagged customers, and if needed build an uplift model that predicts the change in churn probability caused by the call, targeting customers with the largest uplift rather than the highest risk.

What if you run k-means on unscaled features where income is in dollars and age in years?What if

Euclidean distance will be dominated by income, whose differences are thousands of times larger, so the clusters will be income bands and age will be ignored. Standardise (or otherwise put features on comparable scales, deliberately weighting the important ones) before any distance-based method: k-means, k-NN, SVM with RBF kernel, PCA.

AUC (ROC-AUC)
Area under the ROC curve; the probability that a random positive is scored above a random negative.

Area under the precision-recall curve, a summary that reflects the base rate of positives.

Bootstrap aggregating: training models on bootstrap samples and averaging them to reduce variance.

Error of the average model over training sets relative to the truth; the error a model family makes even with unlimited data.

A sample of n rows drawn with replacement from n rows; contains about 63 percent of distinct rows.
Calibration
Agreement between predicted probabilities and observed frequencies.
Class weight
A multiplier on the loss of one class's rows, used against imbalance; shifts scores and harms calibration.
Confusion matrix
The table of true positives, false positives, false negatives and true negatives at one threshold.

Repeated training and validation on different folds of the data to estimate performance and its spread.
DBSCAN
Density-based clustering that grows clusters from core points within a radius and labels sparse points as noise.

Stopping training when the validation loss stops improving; the standard way to choose the number of boosting rounds.

Average gap between predicted probability and observed rate across score bins, weighted by bin size.

An iterative algorithm for models with hidden variables: compute soft assignments, then re-estimate parameters.

A system that computes, stores and serves feature values with timestamps for both training and production.

An ensemble built by adding small trees one at a time, each fitted to the negative gradient of the loss.

\(1 - \sum_k p_k^2\); the probability that two random rows in a node have different labels.

A density model that is a weighted sum of Gaussians, used for soft, elliptical clustering.

\(\max(0, 1 - y f(x))\); the SVM loss, zero for points correctly classified beyond the margin.
Hyperparameter
A setting chosen by validation rather than learned by the optimiser, such as tree depth or regularisation strength.
Inertia
The k-means objective: the sum of squared distances from points to their cluster centres.
Kernel
A function computing the dot product of two inputs in an implicit feature space, such as the RBF kernel.
k-means
Clustering that alternates assigning points to the nearest centre and moving centres to their means.
k-nearest neighbours (k-NN)
Prediction by vote or average of the k closest training examples.
Lasso (L1)
Linear regression with a penalty on the sum of absolute weights; produces exact zeros.
Leakage
Information in training that will not be available at prediction time, inflating offline scores.
Learning curve
Training and validation scores as a function of training-set size; separates bias from variance problems.
Learning rate (shrinkage)
In boosting, the factor by which each new tree is scaled before being added.
Log loss
Negative log-likelihood of the labels under predicted probabilities; binary cross-entropy.

\(\log\frac{p}{1-p}\); the linear score of logistic regression.

Choosing parameters that make the observed data most probable under the model.
Naive Bayes
A generative classifier that applies Bayes' rule assuming features are independent given the class.

An outer CV loop for evaluation around an inner CV loop for model selection.

Rows not drawn into a tree's bootstrap sample; used as free validation in random forests.

Fitting accidents of the training sample: low training error, high test error.
PCA
Principal component analysis: projection onto orthogonal directions of decreasing variance, via the SVD.

The drop in a held-out score when one feature's values are shuffled.
Pipeline
One object chaining all fitted preprocessing steps and the model, refitted together in each fold.

TP / (TP + FP): the share of flagged cases that are truly positive.

Bagged deep trees that also sample a random subset of features at each split.

TP / (TP + FN): the share of positives that are flagged.

Any constraint that limits model flexibility to reduce variance.

Linear regression with a penalty on the sum of squared weights.

True positive rate against false positive rate over all thresholds.
SHAP
Feature attributions for one prediction based on Shapley values; contributions add up to the prediction.
SMOTE
Oversampling that creates synthetic minority examples by interpolating between neighbours.
Support vector
A training point on or inside the SVM margin; the only points that determine the boundary.
Target encoding
Replacing a category with the average label of its rows; must be computed out of fold to avoid leakage.
